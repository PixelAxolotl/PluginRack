# PluginRack Rack-First UI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`-`) syntax for tracking.

**Goal:** Migrate the JUCE desktop app from a dense VoiceMeeter-style console to the rack-first studio workspace described in `ui.md`, while preserving all audio behavior.

**Architecture:** Introduce an application shell with a persistent toolbar and view navigation (Racks/Mixer/Routing/Settings), make the rack view the default, render plugin chains as horizontal modules around the existing insert model, add chain selection + focused plugin-editor behavior, move mixer controls into a dedicated mixer view, then refine meters/state/sizing. Remove legacy layout only after equivalent behavior is verified.

**Tech Stack:** C++20, JUCE 9, MSVC `/W4 /WX`, no new dependencies. Reuses existing `AudioEngine`, `ConsoleLookAndFeel`, `Theme` tokens.

**Spec:** original design doc removed from repo root; plan is self-contained.

## Global Constraints

- Windows 10/11 x64 JUCE desktop app; VST3 only.
- Live-safe: no blocking UI operation, plugin scan, or editor opening may stall audio.
- Theme tokens only in UI; hover/pressed/disabled states on new controls.
- Non-color indicators for bypass/mute/solo/failed states; keyboard focus visible.
- Minimum window 1180x700, default 1600x900; targets 1600x900 and 1180x700.
- Preserve all existing audio behavior and engine semantics (default 3 outputs + 1 channel, routing via send gain, insert slots, latency label, meters).
- Conventional Commit messages, no AI attribution trailers.
- Never break `pluginrack_app` build (`/W4 /WX`).

## Review Focus

- Audio-thread safety must survive the UI migration: UI mutations go through `AudioEngine` under `stateLock`; plugin load/remove/editor-open use `SafePointer` + `callAsync`. (All tasks)
- No view may drop a working control (routing inline, mute/solo, fader, trim, pan, inserts) before an equivalent exists. (Tasks 2-5)
- Meters must keep 30 Hz decay and remain more prominent than the narrow strips. (Task 6)
- Screenshot verification at both target sizes must show no clipping/overflow. (Tasks 1-6)
- Active audio errors must be visible in the toolbar, not buried in a menu. (Task 1)
