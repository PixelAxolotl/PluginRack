# Output FX Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give every output/master strip a 4-slot VST3 rack identical in behavior to channel strips.

**Architecture:** Extend the core Scene model (Output gains `inserts`, schema v1→v2 with auto-migrate), process output chains in both render paths (core `MixerEngine` for CLI/tests, app `AudioEngine` for live), and hang a compact rack UI on widened output strips behind a small host interface.

**Tech Stack:** C++20, JUCE 9 (app), JUCE-free core + nlohmann_json, MSVC `/W4 /WX`, VST3 hosting only, no new dependencies.

**Spec:** `docs/superpowers/specs/2026-10-29-output-fx-design.md`

## Global Constraints

- C++20, MSVC `/W4 /WX` clean (warnings are errors).
- No new dependencies (JUCE, nlohmann_json only).
- VST3 only; VST2 best-effort rule unchanged.
- Theme tokens only in UI; hover/pressed/disabled states on new controls.
- Conventional Commit messages, no AI attribution trailers.
- Never break `ctest --preset dev` (44 tests green at start).

## Review Focus

- A v1 scene file (no output inserts) loads with empty output racks and saves as v2 — covered in Task 1.
- A 5th insert on a channel or output is rejected with a message; the first 4 are untouched — covered in Task 3.
- A bypassed output insert passes audio bit-identically — covered in Task 2.
- Removing an output that holds inserts drops its chains and routes; render stays valid — covered in Task 3.
- Latency report includes the clock output's insert sum and excludes other outputs' — covered in Task 3.
